# 舒尔特方格 · 前后端分离改造设计

日期：2026-08-27
状态：已确认

## 背景与目标

现状是一个目录内的单体项目：`index.html`（原生 JS 单页）+ `server.js`（Node 内置 http + sqlite，同时承担 API 与静态文件服务）。

目标（动机：学习/练手标准工程化）：

1. 前后端职责分离：前端 Vue 3 + Vite，后端 Express，各自独立 npm 包与依赖。
2. 完整保留现有青玉国风视觉样式（配色、衬线字体、动画、弹层）。
3. 运行方式不变：本机 + 局域网，日常使用仍是"一个 start.bat → 打开 3000 端口"。
4. 数据兼容：复用现有 `schulte.db`（users / records / sessions 表结构一字不改），已有账号与记录完好。

│  ├─ server.js                 # 入口：express 配置、静态托管 dist、错误中间件
│  ├─ db.js                     # node:sqlite 初始化 + 建表（复用现有 schulte.db）

## 运行模式

| 模式 | 命令 | 端口 | 说明 |
|---|---|---|---|
| 开发 | `npm run dev`（concurrently 同起两端） | Vite 5173 + Express 3000 | Vite 代理 `/api` → 3000，前端无 CORS |
| 生产 | `npm run build` 后 `npm start` | Express 3000 托管 dist + API 同源 | 单进程 |

- 开发时页面访问 `http://localhost:5173`。
- 生产（start.bat 场景）页面与 API 同源，局域网手机访问 `http://<本机IP>:3000`。
- 第一次使用 start.bat 前需先 `npm run build`；build 产物不入库（node_modules 与 dist 加入 .gitignore）。

## 前端设计

### state.js（reactive 单例，不引入 Pinia）

```
size、nextNum、mistakes、startTime、playing、muted、
token、user、records（{ '5': bestTime }）
```

### 游戏逻辑归属

- 洗牌（费雪-耶茨）、计时 rAF 循环、`onCell` 判定（正确/失误/完成）、评分 `ratingFor` 集中在 `SchulteBoard.vue` 内部，通过 emit 通知父组件（如结算事件）。
- 其余组件只读写 state，不复制游戏逻辑。

### 样式迁移

- 全局（style.css）：CSS 变量、body 背景（人物插画 + 遮罩）、滚动锁定、user-select、fadeUp/cellIn 等 keyframes。
- 组件（scoped）：棋盘、弹层、控制区等各自样式原样迁入，保持视觉一致。

### API 调用

`api.js` 保持现有行为：

- 自动注入 `x-token`（localStorage 持久化 `schulte-token` / `schulte-user`）。
- 网络失败 → `{ ok:false, error:'无法连接服务器…' }`。
- 401 → 清空登录态并弹出登录窗。
- 成功后返回服务器响应。

## 后端设计

- Express 5（当前 npm 默认安装版本），EJS 不需要。
- db.js：`node:sqlite` DatabaseSync，建表语句完全复制现有 server.js 内容，确保复用现有 schulte.db。
- auth.js：scrypt + random token，中间件 `requireAuth`（无/坏 token → 401「登录已失效，请重新登录」）。
- 路由返回结构与现有 API 完全一致（`{ ok, token, username }` / `{ ok, records }` / `{ ok, best, isNewRecord }`），前端 api.js 无需改语义。
- `express.json({ limit: '100kb' })`。
- 统一错误中间件：JSON 响应、不泄露堆栈。
- 生产环境托管 `frontend/dist`（本项目单页无客户端路由，直接静态服务即可，无需回退规则）。
- 端口：`process.env.PORT` 或 `process.argv[2]` 或 3000（保持与现在 start.bat 的兼容习惯）。

## 错误处理

- 后端：错误中间件统一 JSON；请求体超 100kb 拒绝；CORS 仅开发代理不需要，生产同源，均无需跨域头（移除原 `Access-Control-Allow-Origin: *`，本地单机场景由代理/同源解决）。
- 前端：api.js 归一错误对象，登录窗内展示错误文案。

## 兼容与迁移

- schulte.db 直接复用，无迁移脚本。
- 原 `index.html` 替换为 Vite 入口（外层保留标题/图标/字体链接）。
- 登录态 localStorage 键名不变，改造后旧登录状态继续有效。
- 背景图 `8318ebad4821d90fee2621d30c4fece2.jpg` 移入 `frontend/public/`。

## 范围外（YAGNI）

- 不引入 Pinia、TypeScript、UI 组件库。
- 不做多端（小程序/App）API 扩展。
- 不做公网部署（无 CORS 需求）。
- 不重构现有数据库结构。
